1. Introduction

Apex Smiles is a one-page HTML5 template for cosmetic, restorative and family dental practices. It is built for conversion: a clear hero with a single primary call to action, trust signals, treatments with starting prices, a clinician profile, transparent pricing, patient stories, a FAQ and a contact section with opening hours and a privacy-friendly map.

  • Semantic HTML5, BEM class names and readable, unminified CSS and JavaScript.
  • No frameworks, no jQuery, no web-font downloads and no npm dependencies.
  • Mobile first, with automatic dark mode.
  • Built to WCAG 2.2 AA: visible focus, keyboard support, 4.5:1 text contrast and reduced-motion support.
  • Local SEO ready: Dentist structured data (JSON-LD), Open Graph tags and a social sharing image.

All names, prices, reviews, addresses and phone numbers in the demo are fictional sample content. Replace them with your practice's real details before you publish.

3. Getting started

Preview on your computer

Double-click apex-smiles-html/index.html to open it in your browser. For the most faithful preview, serve the folder locally, for example with Python 3:

cd apex-smiles-html
python -m http.server 8000

Then visit http://localhost:8000.

Publish to your server

  1. Complete the SEO checklist, in particular replacing every example.com.
  2. Upload the contents of apex-smiles-html/ (not the folder itself) to your web root, for example public_html/.
  3. Serve the site over HTTPS.

Every path in the template is relative, so it also works from a sub-folder such as example.com/clinic/. File names are lowercase; keep them that way, because most Linux servers treat Hero.svg and hero.svg as different files.

4. Editing content

All text lives in index.html. Each section is wrapped in comments so it is easy to find:

SectionAnchorWhat to edit
Menu#primary-navigationOne <li> per link in .site-nav__list. Point each href at a section anchor from this table; when you add or remove a section, update its menu link too
Hero#heroHeadline, introduction, buttons, the three reassurance ticks and the rating card
Trust bar#trust-barFour key figures; add or remove <li> items freely
Services#servicesOne <li class="service-card"> per treatment, with duration and starting price
About the doctor#about-doctorPortrait, credentials, highlights and quote
Pricing#pricingOne <li class="pricing-card"> per plan; add pricing-card--featured to highlight one
Testimonials#testimonialsOne <li class="testimonials__item"> per review, plus the summary rating
FAQ#faqOne <details class="faq__item"> per question
Contact#contactAddress, phone, email, opening hours and map

Lists and grids adapt to any number of items, so you can add a fifth service or a fourth pricing plan without touching the CSS.

Reviews and medical claims. Publish only genuine patient reviews, with the patient's written consent and an accurate source and date. Avoid promises such as "painless" or "guaranteed results"; dental boards and consumer-protection rules (for example the US FTC rule on consumer reviews) treat them as misleading.

Phone numbers and email

Search index.html for 555 and apexsmiles.example and replace every match, including the tel: and mailto: links. Write tel: numbers in international format, for example tel:+15125550142.

5. Colours and typography

The whole look is driven by design tokens at the top of assets/css/style.css, in the :root block. Change a token once and every component follows.

TokenDefaultUsed for
--color-primary#0b3b60Primary buttons, heading accents, prices
--color-accent#00a896Decorative accents only (not for text)
--color-accent-strong#007a6cLinks, ticks, focus rings, badges
--color-bg / --color-surface#f8fafc / #ffffffPage background / cards
--color-text / --color-muted#1e293b / #64748bBody text / secondary text
--color-star#b07d0aRating stars

Dark mode follows the visitor's system setting. Its colours are set in the @media (prefers-color-scheme: dark) block right below :root; adjust them together with the light values. To turn dark mode off, add data-theme="light" to the <html> tag.

Keep text at a contrast ratio of at least 4.5:1 against its background (3:1 for borders and icons). Free checkers such as the WebAIM Contrast Checker make this quick.

Fonts

The template uses system fonts, so nothing is downloaded and there is no font licence to manage: --font-sans for text and --font-display (system serifs) for figures such as prices and statistics. To use a web font, load it in <head> and add its name to the front of the relevant token.

Breakpoints

Styles are mobile first, with min-width media queries at 768px, 992px and 1200px. Below 992px the menu opens as a drawer from the toggle button; from 992px it sits in the header bar. The 992px value also appears once in assets/js/main.js (DESKTOP_QUERY): if you change it, change it in both files.

Using a photo for the hero

The package ships a vector hero (hero-studio.svg). To use your own photo instead, export it at three widths in WebP with a JPEG fallback, save the six files under the names below in assets/images/hero/, and replace the hero <img> with:

<picture>
  <source type="image/webp"
    srcset="assets/images/hero/hero-640.webp 640w, assets/images/hero/hero-960.webp 960w, assets/images/hero/hero-1200.webp 1200w"
    sizes="(min-width: 992px) 45vw, 100vw">
  <img class="hero__image" src="assets/images/hero/hero-1200.jpg"
    srcset="assets/images/hero/hero-640.jpg 640w, assets/images/hero/hero-960.jpg 960w, assets/images/hero/hero-1200.jpg 1200w"
    sizes="(min-width: 992px) 45vw, 100vw"
    alt="Describe the photo" width="1200" height="1500"
    fetchpriority="high" decoding="async">
</picture>

Keep fetchpriority="high" and never add loading="lazy" to the hero: it is the first thing visitors see. Images further down the page (such as the portrait) keep loading="lazy". Always set width and height to the file's real proportions so the page does not jump while loading, and write alt text that describes the photo.

7. SEO and metadata

Before publishing, open index.html and search for example.com. Replace every match with your real address (with https://):

  • <link rel="canonical">
  • og:url, og:image and twitter:image (social cards need absolute URLs)
  • Every URL inside the application/ld+json block

Then update:

  • <title>, <meta name="description">, og:title, og:description, twitter:title and twitter:description, with your practice name and city.
  • The JSON-LD block: name, address, geo coordinates, phone, email, opening hours, founder and treatments. Keep it identical to what the page shows; search engines penalise mismatches.

Do not add star ratings to the JSON-LD. Google does not show ratings a business publishes about itself, and treats them as spam. The visible rating on the page is fine.

Opening hours that do not repeat every week (such as "2nd and 4th Saturday") cannot be expressed in openingHoursSpecification, so the template leaves them out of the JSON-LD. Do not list days you are not always open.

Validate the result with Google's Rich Results Test and the Schema Markup Validator after publishing.

8. Map

The contact section shows a lightweight map placeholder with a "Get directions" link and a "Show interactive map" button. Google Maps is only loaded when the visitor presses the button, which keeps the page fast and sets no third-party cookies before the visitor chooses to.

Edit the <figure class="map-embed"> element:

  • data-map-src: the address of the embedded map. For production, create a free key for the Google Maps Embed API and use https://www.google.com/maps/embed/v1/place?key=YOUR_KEY&q=YOUR+ADDRESS. An OpenStreetMap embed (https://www.openstreetmap.org/export/embed.html?…) also works and needs no key.
  • data-map-title: a short description of the map for screen-reader users.
  • The "Get directions" link: replace the address after query=.

For safety, only https:// maps from www.google.com, maps.google.com and www.openstreetmap.org are loaded. To allow another provider, add its host name to MAP_HOSTS in assets/js/main.js.

9. JavaScript

assets/js/main.js is plain, readable JavaScript with no libraries. It powers the mobile menu drawer and the click-to-load map. Everything else (the FAQ, pricing and layout) works without JavaScript, and without JavaScript the menu simply shows as a list under the logo. The script exposes nothing on window, so it cannot clash with plugins or other scripts.

10. Accessibility

  • Skip link, landmarks and a logical heading order.
  • Visible keyboard focus on every interactive element, with 44 px touch targets.
  • The mobile menu is announced as expanded or collapsed. While it is open, keyboard and screen-reader focus stays inside it, and Escape or a tap outside closes it and returns focus to the menu button.
  • The FAQ uses native <details> elements, which work with keyboards and screen readers by default.
  • Star ratings are announced as text (for example "Rated 5 out of 5").
  • Animations are reduced to near-zero for visitors who ask their system for reduced motion.

When you edit content, give every image a meaningful alt text (or alt="" if it is purely decorative) and keep headings in order.

11. Browser support

The latest two versions of Chrome, Edge, Firefox and Safari, on desktop and mobile. The template uses modern CSS such as color-mix() and intrinsic grid layouts, which these browsers support. Internet Explorer is not supported.
